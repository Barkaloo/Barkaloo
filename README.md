# Barkaloo

Personal English-learning PWA based on the supplied `Barkaloo-English-v2.4.html`,
with account-based Supabase synchronization added in v2.5.

Open https://barkaloo-web.vercel.app on both devices. On Home, use the
**Синхронизация** panel to create an account or sign in. If confirmation is enabled,
confirm the email before signing in. Use the same account on phone and computer.
Words, vocabulary and grammar progress, calendar, statistics, translations and
settings are synchronized automatically after edits, on reconnect/focus and every
15 seconds while visible. Local use remains available offline. Signing out on one
device does not sign out the other.

When both devices have unsent changes, choose the cloud or local version explicitly.
Before loading cloud data, the app retains the first local snapshot and the most
recent pre-sync snapshot; their download buttons are in the synchronization panel.
No password or privileged Supabase key is stored by the app.

### Supabase backend

The app reuses the original project `jhvqlhwoiyyuzsekwqut` and its public browser
key, configured in `source/cloud-ui.js`. The backend needs email/password Auth and
`public.app_state` with `user_id` (UUID primary key), `state` (JSONB), and
`updated_at` (timestamptz). If the table or its policies have not been set up, run
`supabase/schema.sql` in that project's SQL Editor. The script enforces access
only to the signed-in user's row, including a restrictive policy to constrain any
pre-existing permissive policies. Never replace the browser key with a service key.

Conditional writes compare the last `updated_at` revision to prevent an intervening
save from another device being silently overwritten. The provided database trigger
sets monotonic server timestamps; the client also supports the original schema.
Configure Auth's site URL/allowed redirects to the production site for email links.

This environment's network policy blocks direct access to the Supabase host.
Backend availability, email delivery and production RLS were therefore **not**
verified here. The automated integration tests below simulate Supabase; they do
not establish the state of the live database. A missing table is reported in the UI
without replacing local data or displaying a successful synchronization status.

### Development

Requires Node.js 18+ and Python 3 for the local HTTP server. No npm install is needed.

```sh
node --test archive.test.cjs cloud-sync.test.cjs
node build.cjs
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Both `index.html` and `dist/index.html` contain the complete app. They do not fetch
`archive.json` or base64 chunks at runtime. Serve the repository root or `dist`
over HTTP/HTTPS. HTTP on localhost or HTTPS enables service-worker installation
for offline use after the first load.
External dictionary downloads and cloud sync require Internet access.

`node test/cloud-browser.cjs` exercises sign-in, two independent desktop/mobile
browser contexts, automatic sync, offline reload/reconnect, conflict resolution,
backups and logout against an explicitly simulated Supabase API. It requires the
Playwright module and Chromium at `/usr/bin/chromium`, both provided in this cloud
environment. It does not contact or create accounts in the production project.

For Vercel, `vercel.json` sets the build command to `node build.cjs` and the output
directory to `dist`. Publish the full checkout, including the build tools, source,
`archive.json` and the active chunks. For other static hosts, upload the contents
of `dist`. If uploading only `index.html`, the app still opens, but installable PWA
and offline caching require the accompanying `sw.js`, manifest and icon.

Edit the readable `source/app.html`, `source/cloud-sync.js` and `source/cloud-ui.js`,
then run `node pack.cjs` and `node build.cjs`. The original uploaded HTML is preserved
in Git at commit `6c8ee6f` before the v2.5 changes. Do not edit base64 chunks by
hand. `archive.json` lists the active chunks and SHA-256 digests of the gzip and
HTML source; the build rejects damaged archives. Cloud modules, the manifest link
and service-worker registration are inlined during the build, keeping the app
self-contained at runtime. Old `app-11*.b64` and `bundle-*.b64` are unused historical
artifacts and are not loaded or cached. `index.html` is generated by the build;
change `source/app.html` rather than editing the generated page.

### Themes and translation answers

The theme selector offers system, light and dark modes. Its value is stored in
`settings.theme`, included in backups and synchronized with the other settings.
Older backups without a theme follow the device preference.

Dictionary and vocabulary practice combine saved translations with bundled core
meanings and additional Russian synonyms. Saved translations are never replaced
by these additions. Use the pencil button to edit a personal translation; separate
accepted alternatives with semicolons. English → Russian accepts any complete
listed variant, ignoring case, repeated whitespace, trailing sentence punctuation
and е/ё. Russian → English still requires the target English word; production
progress rules are unchanged. Built-in additions work offline and do not require
a database migration or new Supabase permissions.

The browser test also checks legacy data preservation, all three theme modes,
synchronizing the selected theme and accepting synonyms in each vocabulary level.

### Structured trainer lessons

- Daily: the 100 distinct passive words with the lowest `uses`, regardless of
  correctness; alphabetic ties. A smaller passive vocabulary gives a smaller lesson.
- Mistakes: up to 100 passive words with the lowest lifetime `correct / (correct +
  wrong)`. Untested words have no accuracy and are excluded. Ties prefer more
  mistakes, then fewer uses, then alphabetical order.
- New words: ten currently general/unknown core words, with 2–3 highlighted
  bilingual example sentences, then an English → Russian test on the same words.
  Selection prefers fewer previous lesson attempts, then core frequency rank.
  Viewing cards does not count as an answer. Five correct English → Russian answers, accumulated across all sources, move
  a word to passive, carrying over all prior production attempts, including errors.

Each queue is frozen at the start. Answers count once, including explicit
“Не знаю” answers. Passive words keep the existing production/promotion rules.
General-word production counters live in `coreProgress` until promotion; the
General dictionary shows those counts. Completed answers also mark the study day.
`settings.trainerLesson` stores the active queue, phase and results in the existing
backup/Supabase payload, so reload and sync can resume without double-counting.
There is one current lesson at a time; it can be finished early without losing
answered-word statistics. Starting again builds a new queue from current counts.
No Supabase schema or credential changes are required.

Examples cover all 1,500 bundled core headwords and work offline. Dataset
attribution and the CC BY 4.0 license are in `third_party/SMARTool.md` and
`third_party/SMARTool-LICENSE.txt`; original supplements are in
`source/lesson-example-supplement.txt`. The build inlines `source/lessons.js` and
`source/lesson-examples.json` so root/dist static hosting remains self-contained.

Validation: `node --test archive.test.cjs cloud-sync.test.cjs lessons.test.cjs`,
`node test/cloud-browser.cjs`, and `node test/lesson-browser.cjs`. The latter
completes all 100 daily questions, verifies rankings and counters, reload/resume,
10 learning cards followed by testing, and simulated two-device synchronization.

### Vocabulary levels and chat lesson imports

All new manual, bulk and imported words enter the general bank. Re-adding a word
updates its translation without moving its level or clearing its history. Custom
bank entries survive reload and Supabase sync; the bank is not truncated to 1500.
Automatic level changes follow the answer rules below. Trainer level controls
allow explicit manual overrides while preserving translations and counters.

`source/progression.js` is the common production policy for every answer source:

- General → passive: five cumulative correct **English → Russian** recognitions,
  not necessarily consecutive. Recognition statistics stay in `coreProgress`.
- Passive → active: at least five ordered **Russian → English** attempts, with
  at least four correct in the most recent five.
- Active → passive: fewer than seven correct in a full latest-ten window, or
  three consecutive incorrect Russian → English attempts. Exactly 70% stays active.
- Opposite-direction attempts never enter the production window. Viewing cards
  never counts as answering. Levels and known history are preserved when loading
  existing data; the common policy evaluates subsequent real attempts.

The new-word lesson now tests English → Russian, contributing to recognition
without promoting after a single answer. Older saved in-progress new-word lessons
keep their original direction so they can finish without reinterpreting answers.
Production attempts made while still general are recorded but cannot bypass the
recognition gate. Existing translations and cumulative counters are retained.

To import statistics from a chat lesson, use the Home import panel. Include a
unique lesson `id` and each word's attempts **in chronological order**:

```json
{
  "id": "english-2026-11-03-1",
  "date": "2026-11-03",
  "words": [{
    "word": "although",
    "translation": "хотя",
    "attempts": [
      {"direction": "en-ru", "correct": true},
      {"direction": "ru-en", "correct": false}
    ]
  }]
}
```

Re-importing an `id` is ignored. Without an `id`, an exact payload SHA-256 provides
duplicate protection. A supplied `kind` cannot grant a level. Legacy aggregate
`correct`/`wrong` totals default to Russian → English; `direction: "en-ru"` or
`recognitionCorrect`/`recognitionWrong` can supply recognition totals. Unordered
production totals update counters but never invent last-five/last-ten history:
previous history is retained, with a new ordered evaluation window started after
the gap. `trainer` totals from chat imports are ignored by trainer counters; imported
word recognition/production statistics still update the dictionary and levels.
The existing backup and Supabase payload carry all histories and import IDs.

Additional validation: `node --test progression.test.cjs` and
`node test/progression-browser.cjs` exercise exact boundaries, mixed sources,
no premature promotion, three-error demotion, import deduplication and reload.

### Trainer controls

The Dictionary has a separate **Незнакомые** tab: only bank entries whose level
is general, excluding passive/active vocabulary. The original General Bank tab
still shows every level and supports its filters and adding words.

Enter checks the current answer, then advances to the next question on the next
press. The answered input remains focused and read-only instead of disabled.
Learning cards also advance with Enter. Dropdowns, audio buttons, timer buttons
and manual-level buttons retain their normal keyboard actions.

The current word can be moved manually between general, passive and active in
both structured lessons (including study cards) and free vocabulary practice.
No answer is invented or removed: translations, counters, raw production history
and recognition totals remain intact. A manual change starts a new automatic
production evaluation window. Moving to general stores a recognition baseline,
so five *additional* correct EN → RU answers are needed to auto-promote again.
The word remains in the current frozen lesson queue; subsequent actual attempts
are still counted once. Histories, baselines and levels use the existing sync data.

The trainer timer counts active time, with Pause/Continue and Reset. Starting a
new lesson resets it; leaving Trainer, hiding the tab or completing a lesson
pauses it. Accumulated time is saved in `settings.trainerTimer`; time spent away
or with the browser closed is not added on reload. The display updates locally
without creating per-second Supabase writes.

Feedback after vocabulary/lesson checks has an audio button for the English
headword (also when the checked answer is Russian). Verb feedback pronounces the
three English forms. Audio uses the existing browser speech and accent settings.

Validation: `node test/trainer-controls-browser.cjs` checks filtering, data-preserving
manual moves, real Enter key presses in study/free/structured modes, speech targets,
exactly-once counters, timer pause/navigation/reset/reload and mobile layout.

### Chat statistics, branding and browser navigation

Chat lesson import is dictionary-only: ordered attempts, legacy aggregates and
recognition totals still affect the word's counters, history and automatic level
transitions. They do not increase `stats.vocabCorrect`, `stats.vocabWrong`,
`stats.verbCorrect` or `stats.verbWrong`, and do not add answers to a trainer lesson.
Real exercise answers still count normally. Existing historical totals are retained;
previously mixed data is not guessed or subtracted without source information.

The Home vocabulary card is labeled **Bank**; dictionary bank search is **Search**.
The sidebar logo loads the supplied animated GIF from its Pinterest CDN URL.
If the GIF is unavailable, the logo tries the supplied static Pinterest JPG.
`source/logo-character.png` is the embedded transparent last-resort fallback used
if both remote images are unavailable or the app is offline. The image source is kept as a GIF to preserve
animation; the original reference is not converted to a static picture. The whole sidebar brand
(image and Barkaloo text) is a home link, also supporting normal modified link clicks.

Sections use same-document hash routes (`#/home`, `#/dictionary`, `#/grammar`,
`#/trainer`) with `pushState`/`popstate`. Browser Back/Forward, including extra mouse
buttons, traverse visited sections without reloading or losing the running app.
Reload/direct routes restore the requested section. The app does not trap browser
history at its first entry; going back beyond the app's history works normally.

`node test/navigation-import-browser.cjs` checks ordered/aggregate/global imports,
unchanged trainer counts, live exercise counting, word-stat persistence, both brand
click targets, native Chromium back/forward mouse events, same-document navigation,
route reload and mobile layout. The archive test verifies the logo is embedded.

The logo GIF destination is `i.pinimg.com`. This environment currently blocks its
HTTP CONNECT request (403), so real CDN delivery cannot be validated here. A
browser test intercepts the exact URL with a two-frame GIF to verify animated-image
loading and tests the embedded PNG fallback separately on a network error.
