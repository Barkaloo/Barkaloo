# Barkaloo Fit

Спортивный прототип на основе оформления английского Barkaloo.

## Запуск

```sh
python3 -m http.server 8001 --bind 127.0.0.1 --directory /workspace/Barkaloo
```

Приложение находится по пути `/fitness/`. `node build.cjs` копирует его в `dist/fitness/` вместе с английским сайтом.

## Разделы

1. Главная: исходный календарь, импорт данных из ChatGPT, цель веса со шкалой и шесть панелей в порядке «Тренировки», «Время тренировок», «Средняя тренировка», «Дистанция», «Время на дорожке», «Серия активности», вход в аккаунт. Удалены недельная цель тренировок, последние тренировки, выбор периода на главной и подвал.
2. Журнал тренировок: календарь на всю ширину блока записей со своими отметками, выбор календарного месяца и таблицы силовых тренировок, сгруппированные по неделям. Поиск и выбор типа убраны.
3. Учёт КБЖУ и вес: ежедневный журнал выбранного месяца — Ккал, белки, жиры, углеводы и утренний вес. Доступны добавление, изменение и удаление записи за день, ручной ввод и импорт.
4. Активность: ежедневные отметки дорожки, осанки и предплечий, дистанция и время дорожки, выбор календарного месяца. Сохранение автоматическое.
5. Статистика: произвольный интервал дат и готовые периоды 7/30/90 дней, средний вес, график и недельные средние, КБЖУ, силовые тренировки, дорожка, отметки календарей, активные дни и контрольные антропометрические замеры.

На главной показываются итоги за всё время. Дистанция дорожки учитывает отмеченные сессии из «Активности», тип «Беговая дорожка» либо явно заполненную дистанцию дорожки в старой тренировке. Время дорожки на главной — среднее по сессиям с положительной указанной длительностью; дневная отметка, отдельная запись дорожки или часть силовой тренировки считается одной сессией. Записи без дорожки и без её времени в знаменатель не входят. Если времени нет, отображается «—». Отметка дорожки без чисел не создаёт нулевые дистанцию или время. Уличный бег и велосипед не относятся к дорожке. Среднее время тренировок считается по тренировкам с указанной длительностью. Время задаётся в минутах в форме силовой тренировки и отображается рядом с датой карточки. Старые записи без времени остаются `null`; пустое поле не подменяется нулём и не уменьшает среднее. Если длительность нигде не указана, отображается «—». Серия считается по отметкам календаря, как в английском Barkaloo: если сегодня ещё не отмечен, серия может заканчиваться вчера.

Календарь главной использует `activityDays`, календарь журнала — отдельный `trainingDays`. Изменение одной карты не изменяет другую ни локально, ни через синхронизацию. При чтении старых данных общая карта копируется в две независимые карты один раз, чтобы не потерять прежние отметки; явные пустые карты затем сохраняются пустыми. После обновления перезагрузите сайт на обоих устройствах, чтобы старый клиент больше не записывал прежний формат. Двойной клик мышью или двойное касание даты ставит/снимает отметку; одиночное нажатие ничего не раскрывает. Для клавиатуры доступны Enter/Пробел. Оба календаря отображают 42 дня с соседними месяцами, как английский Barkaloo. Старые даты тренировок становятся начальными отметками; после снятия отметка не возвращается при перезагрузке. Сохранение или импорт новой тренировки отмечает её дату только в журнале, без отметки на главной; удаление карточки не снимает независимую отметку автоматически.

Журнал показывает все силовые тренировки выбранного календарного месяца, независимо от диапазона графиков. Старые записи других видов спорта не удаляются и сохраняются для существующих показателей главной, но не выводятся в силовом журнале. Календарь и блок записей имеют одинаковую ширину; низкие строки сохраняют его компактность. Стрелки календаря и поле «Месяц записей» связаны. Месяцы календарей на главной и в журнале переключаются независимо.

Месячный список разделён на недели и упорядочен от новых тренировок к старым. Все таблицы развёрнуты, видны дата, день недели и количество тренировок за месяц. Колонки: «Упражнение», «Подходы», «Повторы», «RIR». «Добавить карточку» открывает дату, время в минутах и пустую строку таблицы, без типа, названия, самочувствия и кардиополей. Строки можно добавлять/удалять (до 100 упражнений), в повторах и RIR допустимы диапазоны и значения по подходам, например `8 / 8 / 6`. RIR `0` сохраняется как значение. Можно сохранить датированную пустую таблицу и заполнить её позднее. Новые записи имеют `format: "strength-table-v1"` и массив `exercises` со строковыми полями `exercise`, `sets`, `reps`, `rir`. При редактировании старых записей сохраняются прежние длительность, заметки, кардиополя и оригинал импорта.

Импорт сохраняет исходный JSON, распознаёт тренировки, КБЖУ и утренний вес. Для автоматического создания карточек поддерживаются `workout` (объект), `workouts` (массив), `training` или `тренировка`. Дата берётся из самой тренировки, затем из общего поля `date`, иначе из текущей локальной даты. Повторная запись не создаёт дубли. Пример силовой таблицы из ChatGPT:

```json
{"date":"2026-11-04","workout":{"duration":60,"exercises":[{"exercise":"Жим лёжа","sets":3,"reps":"8–10","rir":2},{"exercise":"Присед","sets":4,"reps":"6 / 6 / 5 / 5","rir":"2 / 2 / 1 / 0"}]}}
```

`name` также принимается как название упражнения, `RIR` — как RIR. Если `sets` — массив отдельных подходов, число подходов берётся из его длины, а фактические повторы/RIR объединяются через `/`. Если есть только названия упражнений, остальные ячейки остаются пустыми. Никакие подходы или повторы не выдумываются. Дополнительные исходные поля сохраняются в раскрываемых «Данных из ChatGPT».

Старые незавершённые импорты (`draftWorkouts`) тоже отображаются таблицами и редактируются той же формой. Сохранение переводит их в `workouts`, сохраняя исходные данные. Нутриционные записи без тренировки не создают тренировочных таблиц.

## КБЖУ и утренний вес

Одна запись в `dailyEntries` на календарную дату. Поля: `calories`, `protein`, `fat`, `carbs`, `weight`. Калории — Ккал за день, макронутриенты — граммы, вес — кг утром. Можно вводить только вес или только часть питания; пропущенные значения — `null`, настоящий ноль сохраняется как ноль. Показатели не рассчитываются друг из друга, вес не переносится на соседние дни. Полностью пустая запись не сохраняется; существующую можно удалить. На ПК показана таблица дней месяца, на телефоне — компактные дневные строки со всеми пятью значениями.

Пример импорта:

```json
{"date":"2026-11-04","morningWeight":79.4,"nutrition":{"calories":2200,"protein":150,"fat":70,"carbs":240}}
```

`weight` поддерживается как алиас утреннего веса; `morningWeight` имеет приоритет. Из `nutrition` также принимаются `kcal`, `proteins`, `fats`, `carbohydrates`. Числовые строки с десятичной запятой распознаются. Новый импорт обновляет только переданные поля дня и не стирает остальные. Точный повтор уже сохранённого импорта не перезаписывает последующие ручные изменения. Сохранённые ранее импорты с корректной датой восстанавливаются в дневник один раз при первом чтении старого состояния. Явный `dailyEntries: {}` остаётся пустым после удаления; старые импорты не воскрешают записи. Все дневные записи входят в резервные копии и обычную синхронизацию аккаунта.

## Цель веса

Панель под календарём имеет ту же ширину и заголовок «Цель» по центру. Пользователь задаёт желаемый вес в кг. Старт — среднее последних семи фактических утренних взвешиваний, независимо от пропусков дней; будущие даты исключены. При сохранении цели старт фиксируется и не сдвигается с новыми взвешиваниями. Текущее значение — скользящее среднее последних семи записей. Шкала показывает путь от старта к цели, поддерживает снижение и набор веса и ограничена 0–100%.

Если семи взвешиваний нет, старт, текущее среднее и шкала остаются пустыми; желаемый вес можно сохранить заранее. Старт такой цели фиксируется при появлении седьмой записи. Изменение целевого веса начинает новую цель с новым стартом; повторное сохранение того же веса старт не меняет. Сброс удаляет цель. `weightGoal` хранит `target`, `start`, `createdOn`, `capturedOn`.

## Внетренировочная активность и статистика

`extraActivity` — карта календарных дат с флагами `treadmill`, `posture`, `forearms` и необязательными `distance` (км), `duration` (мин). Осанка и предплечья представлены только отметками. Числа дорожки доступны при отметке; снятие сохраняет введённые значения, но исключает их из итогов. Эти записи не создают силовые тренировки и не отмечают календари.

Статистика использует обе границы выбранного периода включительно. Средний вес и недельные средние считаются по фактическим взвешиваниям; неделя начинается в понедельник и обрезается границами диапазона. КБЖУ усредняются отдельно по дням с соответствующим показателем, рядом указан размер выборки. Пропуски не считаются нулями. Количество силовых берётся из карточек журнала; ручные отметки календарей показываются отдельно. Активные дни — даты с хотя бы одним флагом в «Активности».

Контрольные замеры — одна частично заполненная запись на дату в `measurements`: `chest`, `waist`, `hips`, `arm`, `thigh`, `calf`, `neck` (окружности в см). Можно добавить, изменить или удалить запись. История фильтруется общим интервалом статистики. Все новые поля входят в обычную синхронизацию и резервные копии; первый вход учитывает наличие локальных целей, дневников и замеров даже при отсутствии тренировок.

Импорт также принимает `activity` и `measurements` за общую дату:

```json
{"date":"2026-11-05","activity":{"treadmill":true,"distance":2.5,"duration":30,"posture":true,"forearms":false},"measurements":{"waist":84,"chest":100}}
```

Новый импорт обновляет только переданные поля; точный повтор не перезаписывает ручные изменения.

## Аккаунт

Используются тот же публичный Supabase-проект, аккаунты и RLS-таблица `app_state`, что в английском сайте. Фитнес хранится в отдельном JSON-разделе `state.settings.barkalooFit`; словарь и английские показатели сохраняются. Обновления проверяют `updated_at`, поэтому конкурентные записи не перезаписываются молча. Английский клиент также сохраняет фитнес-раздел при записи и исключает его из сравнения английской статистики. Для защиты от старого открытого клиента обновите вкладку английского Barkaloo после развёртывания.

Фитнес имеет отдельные ключи сессии, ревизии, владельца и резервных копий в localStorage. Старые записи `ritm.workouts.v1` читаются без миграции. Синхронизация выполняется после правки, при возвращении сети/фокуса и каждые 15 секунд в видимой вкладке. Конфликты требуют выбора версии; перед загрузкой облака сохраняется локальная копия. Выход не удаляет локальные записи. На компьютере в аккаунте также доступны резервные копии JSON. На телефоне кнопки копий и блок экспорта/восстановления скрыты, а панель аккаунта компактна: почта, синхронизация, выход и небольшой статус. Сами копии по-прежнему сохраняются, и скрытие кнопок их не удаляет.

Существующий аккаунт английского Barkaloo подходит для входа в Fit; повторная регистрация не нужна, и это написано у формы. Для новых аккаунтов добавлены повторный запрос письма с паузой 60 секунд, понятные сообщения о лимитах, fitness redirect URL и проверка сессии при возврате по ссылке подтверждения. Токены удаляются из адреса до проверки аккаунта. Повторный запрос означает принятие запроса почтовым сервисом, а не доказанную доставку письма. Встроенная отправка зависит от SMTP/ограничений Supabase; настройки SMTP и подтверждение почты не изменялись.

## Изображения и публикация

Используются присланные пользователем источники:

- Иконка: `https://i.pinimg.com/736x/9e/b4/54/9eb454bde90e9f6a15e34e91dabd7b9f.jpg`.
- Фон: `https://i.pinimg.com/736x/b7/ee/bc/b7eebc948371791c2888da0e81837fe8.jpg`.

На Vercel (`VERCEL=1`) `scripts/build-fitness-assets.cjs` скачивает изображения с проверкой HTTPS, сохраняет фон без изменения и создаёт квадратные PNG размером 32/128/180/192/512 для вкладки, интерфейса, iOS и Android. Подготовка иконок больше не зависит от успешного скачивания фона. Пропорции фото сохраняются с минимальной подложкой. Нужен `npm ci` (Vercel устанавливает зависимости по lockfile). Сборка локализует ссылки в выходной папке. Если логотип не удалось скачать при сборке, `api/fitness-icon.js` отдаёт его как PNG с того же домена при обращении. Endpoint принимает только фиксированные размеры и скачивает только наш фиксированный источник, без произвольных URL. В manifest всегда указаны PNG 192/512, в Apple touch icon — PNG 180, версия метаданных — 8; внешний JPEG больше не используется как установочная иконка. Если недоступен только фон, его оригинальная HTTPS-ссылка остаётся в CSS, а локальные иконки всё равно создаются. Для полного локального теста fallback endpoint нужен Node/Vercel, обычный Python-сервер обслуживает только статический интерфейс. Локальная сборка без `VERCEL=1` не скачивает изображения.

Фон масштабируется относительно видимой области. На телефоне фиксированный слой изображения обрезается по закруглённым границам всей главной; он не заканчивается посередине панелей при прокрутке и не растягивается на высоту длинного блока. Имя вкладки, manifest и ярлыка — Barkaloo Fit. В шапке главной отображается «Спорт», на остальных вкладках — название раздела; иконок в шапке нет. Логотип в боковом меню сохранён, подпись Training удалена.

## Проверки

```sh
npm ci
npm test
node fitness/test/browser.cjs
node fitness/test/insights-browser.cjs
node fitness/test/auth-browser.cjs
node test/cloud-browser.cjs
```

Тесты проверяют сохранность английских данных, две независимые фитнес-сессии, импорты, офлайн-режим, конфликты, обновление токенов, смену аккаунта, размеры иконок и мобильный интерфейс. Дополнительный сценарий проверяет пустую цель до семи взвешиваний, фиксацию старта, скользящее среднее, дневную активность, периоды статистики и редактирование замеров с синхронизацией между ПК и телефоном. Supabase и изображения в браузерных тестах явно симулируются; тесты не проверяют состояние production-базы или реальную доставку Pinterest.
