# Barkaloo Tutor — MVP

Рабочее приложение React + TypeScript + Tailwind CSS для `/tutor/`. Использует
существующий Supabase Barkaloo. Учебных материалов в поставке нет: только 27
редактируемых разделов «Задание №1» … «Задание №27».

## Что реализовано

- Вход и регистрация через Supabase Auth; восстановление пароля.
- Роль преподавателя в защищённой таблице, самостоятельная регистрация ученика.
- Вложенные темы, редактируемые разделы и прототип в карточке задания.
- Визуальный блочный редактор: заголовок, форматированный текст, изображение,
  видео, KaTeX, таблица, Python/JavaScript, пример, практика, примечание.
- Черновик и отдельный снимок публикации; снятие с публикации без потери истории.
- Точные числовые и строковые ответы, один/несколько вариантов, ручная проверка.
- Настройки раскрытия решения, каждая попытка, повторение, журнал ошибок.
- Прогресс чтения и завершения модулей, реальная статистика и график активности.
- Предпросмотр ученика с отдельным прогрессом и попытками преподавателя.
- Светлая, тёмная и системная темы; адаптивная навигация; экспорт JSON.

## Запуск

Нужны Node.js 22.12+ (в этой среде проверено на 24.22) и npm.

```sh
npm ci
# Скопируйте .env.example в .env.local и заполните два публичных значения.
npm run dev:tutor
```

Открыть `http://127.0.0.1:5173/tutor/`. В этой рабочей копии `.env.local` уже настроен
на подключённый проект Barkaloo; файл исключён из Git. Нужен интернет. Сервер не
использует localStorage вместо базы. Только сессия Auth хранится в браузере, а
sessionStorage запоминает переключатель предпросмотра.

```sh
npm run check:tutor
npm run test:tutor
npm test
npm run build
```

Итог сборки — `dist/`: English в корне, Fit в `/fitness/`, Tutor в `/tutor/`.
В `vercel.json` команда сборки обновлена на `npm run build`. Существующая сборка
English/Fit сохраняется. Их service worker пропускает запросы `/tutor/`, чтобы
не подставлять страницу English при недоступной сети.

## Supabase

Миграции создавались штатной командой Supabase CLI и применены к подключённому
проекту через MCP. Не применяйте их второй раз вручную к этому же проекту.

Для нового проекта примените **обе** миграции из `supabase/migrations` по порядку:

1. `20261115173440_tutor_mvp.sql` — схема, API, политики и бакет.
2. `20261115180823_tutor_review_feedback.sql` — исправление ручной проверки.

`supabase/tutor.sql` — сводная актуальная схема для чтения и изолированных тестов;
`supabase/tutor-storage.sql` — описание Storage. Не выполняйте сводную схему поверх
миграций. `supabase/tutor-smoke.sql` проверяет живой API в транзакции с `ROLLBACK`;
после изменения структуры каталога адаптируйте проверку количества разделов.

### Первый преподаватель

Создайте аккаунт через интерфейс. В SQL Editor от имени администратора БД:

```sql
insert into public.tutor_roles(user_id, role)
select id, 'teacher' from auth.users where lower(email) = lower('YOUR_EMAIL')
on conflict(user_id) do update set role = excluded.role;
```

В подключённом проекте роль уже назначена аккаунту, указанному пользователем.
Ни создание профиля, ни `user_metadata`, ни кнопка в интерфейсе не предоставляют
роль преподавателя. Все новые аккаунты по умолчанию ученики.

Подтверждение регистрации и восстановление пароля требуют настройки Auth:
Site URL и Redirect URLs должны разрешать `https://ВАШ_ДОМЕН/tutor/` и нужный
localhost. Встроенная почта Supabase имеет ограничения; успешный запрос не
гарантирует доставку письма. Существующему подтверждённому аккаунту достаточно
войти с прежними email и паролем. Настройки SMTP и подтверждения в этом проекте
автоматически не изменялись.

## Архитектура и права

```
Supabase Auth
  ├─ tutor_profiles / tutor_roles
  └─ sections → topics (parent_id) → modules (draft blocks)
                                    ├─ tasks → private task_keys
                                    └─ publications (snapshot)
                                        └─ published_tasks → private published_keys
                                            └─ attempts → error journal / analytics
                                    └─ progress (user, module, preview)
```

Клиент вызывает единственный RPC `public.tutor_api(action, p)`. Его обёртка —
SECURITY INVOKER. Внутренняя функция в неэкспонируемой схеме `tutor_private`
использует SECURITY DEFINER как явную границу записи: каждая ветвь проверяет
`auth.uid()`, роль и владельца модуля. У функций фиксирован пустой search_path;
EXECUTE отозван у PUBLIC/anon. Перед открытием частной схемы в Data API нужна
отдельная проверка безопасности; по умолчанию она не открывается.

Все публичные таблицы защищены RLS. У authenticated только SELECT; напрямую
записывать попытки, статусы, роли и материалы нельзя. Таблицы ключей ответов не
имеют клиентских grants; RLS в них намеренно без разрешающих политик. Security
Advisor помечает это как INFO «RLS Enabled No Policy»: это запрет по умолчанию.

`data` возвращает преподавателю его черновики и ключи ответов, ученику — только
опубликованные снимки без ключей. Опубликованные модули MVP доступны всем вошедшим
ученикам. Персональные назначения и группы относятся ко второму этапу.

`attempt` сверяет ответ внутри PostgreSQL. Числа сравниваются через точный numeric,
без JavaScript Number и погрешности. Для строк настраиваются регистр и сжатие
пробелов; пробелы по краям удаляются. Множественный выбор сравнивается как множество.
Идентификатор запроса защищает от дублирования одной отправки при повторном запросе.
Решение выдаётся только после попытки по политике автора. Старые попытки содержат
снимок условия и обратной связи: редактирование задания не переписывает историю.

Журнал ошибок вычисляется из неизменяемой истории попыток. Последний результат
определяет статус; прежний неверный ответ остаётся. Ручную попытку может оценить
только владелец модуля; проверка повторно уже оценённой попытки отклоняется.

Предпросмотр использует тот же опубликованный API, флаг `is_preview` проверяется
базой. Попытки предпросмотра не попадают в статистику реальных учеников. Запрос
preview от ученика отклоняется, а не просто скрывается в UI.

Изображения находятся в приватном бакете `tutor-images`. Только преподаватель
загружает файлы в папку своего модуля. MIME ограничен PNG/JPEG/WebP/GIF, размер —
8 МБ. Клиент дополнительно проверяет сигнатуру. SVG/HTML и перезапись файлов
запрещены. Ученик получает подписанную ссылку на 5 минут только для изображения
из опубликованного модуля; уже выданная ссылка может жить до истечения этих 5 минут
после снятия публикации. Удаление файлов через UI не реализовано, чтобы не ломать
снимки публикаций; неиспользуемые загрузки можно очищать отдельно после аудита ссылок.

Нет service_role ключа в приложении. Исполнение произвольного Python отсутствует.
Видео встраивается только с YouTube/Vimeo либо как HTTPS MP4/WebM. KaTeX работает
с trust:false; текст рендерит схема Tiptap. Заголовки безопасности действуют только
на `/tutor/`.

## Проверенный сценарий

Автоматический тест использует настоящий PostgreSQL в PGlite с ролями и RLS,
не JavaScript-заглушку проверки. Покрыты изоляция пользователей, все пять типов
ответов, ручная проверка, публикация и снятие, идемпотентность, скрытие ответов,
конфликт версии, история и раздельный предпросмотр. Живой Supabase RPC также
проверен внутри транзакции с откатом тестовых записей.

Браузерная проверка выполнялась под существующим аккаунтом преподавателя:
раздел №1 → тема → модуль → текст/таблица/Python/изображение → задача → публикация
→ предпросмотр → неверный и верный ответы → журнал ошибок → перезагрузка.
Технические записи после проверки удаляются; они не являются материалами ЕГЭ.
Подробности и итоговые ограничения — в `VERIFICATION.md`.

## Границы MVP и следующие шаги

Первый этап рассчитан на самостоятельное обучение и публикацию библиотеки одним
преподавателем. Второй этап: связи преподаватель–ученик, персональные назначения,
домашние работы, журнал занятий, карточки учеников, фильтры аналитики по ученику.
Для них можно добавить связанные таблицы с owner_id/student_id и расширить RPC
без переделки редактора и истории попыток.

Для коммерческого многопользовательского продукта потребуются отдельные workspace
и membership, ограничения доступа к публикациям и Storage по назначениям,
пагинация `data`/attempts, аудит действий и лимиты запросов. Не заявляйте эту версию
как готовую систему нескольких независимых преподавателей.

Третий этап (исполнение программ, проверка файлов, платежи) не реализован.
Смена типов задач предусмотрена дискриминатором type и отдельной ветвью проверки.

### Замечания к существующей инфраструктуре

`npm audit` отмечает high-уязвимость в уже существовавшем `sharp@0.34.5` (сборка
ассетов Fit). Новые зависимости Tutor в отчёте не отмечены. Обновление sharp
следует проверить отдельно с визуальной сверкой ассетов Fit:
https://github.com/advisories/GHSA-wq5f-xc86-pv6w .

Security Advisor также сообщает об отключённой проверке утёкших паролей в существующем
Supabase Auth. Эта настройка не менялась; информация:
https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection .

Политики и данные `app_state` не изменяются миграциями Tutor.
