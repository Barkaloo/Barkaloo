# Barkaloo Tutor

Рабочая платформа React + TypeScript + Tailwind CSS для `/tutor/` с настоящим
Supabase Auth, PostgreSQL и Storage. Адрес: https://barkaloo-tutor.vercel.app/tutor/ .
Материалов ЕГЭ в поставке нет: только 27 редактируемых разделов «Задание №1» … «Задание №27».

## Возможности

- Преподаватель входит по email и паролю отдельного аккаунта Barkaloo Tutor.
- В меню преподавателя четыре пункта: главная, ученики, журнал занятий, добавление ученика.
- В меню ученика пять пунктов: главная, журнал занятий, домашние задания, каталог КЕГЭ, мой преподаватель. Настройки доступны в верхней панели.
- Ученики входят по постоянному шестизначному коду без email, пароля и регистрации.
- «Добавить ученика» создаёт аккаунт и код; при первом входе ученик выбирает ник и оформление.
- Карточки учеников, личные заметки, архивирование, просмотр/замена/приостановка кодов.
- Вложенные темы и прототипы; визуальный редактор заголовков, форматированного текста,
  изображений, видео, KaTeX, таблиц, Python/JavaScript, примеров, практики и примечаний.
- Черновики и отдельные снимки публикаций; доступ всем вошедшим или только назначенным.
- Точные числовые/строковые ответы, один/несколько вариантов и ручная проверка.
- Настройки раскрытия решения, история попыток, журнал ошибок и повторение.
- Домашние работы с неизменяемыми снимками условий и проверки, сроком и комментарием.
- Прогресс модулей, журнал занятий и статистика по ученику на основе реальных данных.
- Предпросмотр ученика с отдельными попытками; светлая/тёмная/системная темы; экспорт JSON.

## Запуск и проверки

Нужны Node.js 24 (проверено на 24.22) и npm. Из корня репозитория:

```sh
npm ci
# Скопируйте tutor/.env.example в tutor/.env.local и заполните два публичных значения.
npm run dev:tutor
npm run check:tutor
npm run test:tutor
npm test
npm run build
```

Открыть `http://127.0.0.1:5173/tutor/`. `tutor/.env.local` исключён из Git. Нужен интернет:
учебные данные хранятся в базе. Auth-сессия и предпросмотр хранятся в sessionStorage
текущей вкладки, настройки профиля — в Supabase. Каждая новая вкладка входит
отдельно: можно одновременно работать преподавателем и учеником. Перезагрузка
страницы сохраняет её вход. Новый документ (включая копию вкладки и переход по
истории без восстановления из кеша) начинает отдельный вход. Старый общий вход
из localStorage не импортируется; после обновления войдите заново в каждой вкладке.

`src/lib/tab-auth.ts` даёт каждому документу свой канал уведомлений SDK и через
адаптер сохраняет его токены в sessionStorage. Это изолирует не только хранилище,
но и события SIGNED_IN/TOKEN_REFRESHED/SIGNED_OUT. Выход использует scope:local,
поэтому не отзывает отдельные сеансы других вкладок. Постоянные коды учеников,
роли и серверные проверки доступа сохраняются.

`npm run build` собирает English, Fit и Tutor в `dist/`. Исходники English/Fit не
подменяются. Их service worker пропускает `/tutor/`. `npm run build:tutor` собирает
только Tutor в `tutor/.output/tutor/` для отдельного размещения.

## Размещение

Vercel-проект `barkaloo-tutor`: Root Directory = `tutor`, Node.js 24, Include source
files outside Root Directory = true. `tutor/vercel.json` устанавливает зависимости
из корня, запускает `build:tutor`, отдаёт `.output`, перенаправляет `/` в `/tutor/`
и добавляет CSP/nosniff/DENY только для Tutor. Нужны публичные `VITE_TUTOR_SUPABASE_URL`
и `VITE_TUTOR_SUPABASE_PUBLISHABLE_KEY`; сервисный ключ в Vercel не добавляется.

Короткий домен прикреплён к production этого проекта, поэтому ученикам не нужен
аккаунт Vercel. Защита тестовых размещений сохраняется. Репозиторий подключён;
ветка `feature/barkaloo-tutor` выпускается в production явно после проверки.
English/Fit продолжают работать в отдельном проекте `barkaloo-web`. Слияние в main
и переключение их production этим обновлением не выполняются.

## База и сервер входа

Tutor работает в самостоятельном бесплатном проекте Supabase
`ahhcwqxvsoowjqfjmtua`. У него собственные Auth, PostgreSQL, Storage и Edge Function.
Общей авторизации, синхронизации профилей, статистики или прогресса с другими
сайтами нет. Клиент читает только переменные `VITE_TUTOR_*` из окружения Tutor;
ключ хранения сеанса включает идентификатор проекта. Старые сеансы не переносятся.
После одобренного владельцем переноса его email, UUID и хэша пароля прежний пароль
подходит для первого отдельного входа. Последующие изменения аккаунтов независимы.
В старом проекте ничего не удалялось и не менялось.

На новом Supabase-проекте примените все миграции по порядку. В подключённом проекте
они уже применены через MCP; не запускайте их повторно:

1. `20261115173440_tutor_mvp.sql` — каталог, материалы, попытки, политики, Storage.
2. `20261115180823_tutor_review_feedback.sql` — ручная проверка.
3. `20261116125459_tutor_students_homework_lessons.sql` — ученики, назначения, домашние работы и занятия.
4. `20261116131158_tutor_attempt_timestamps.sql` — фактическое время создания попыток.
5. `20261116165804_tutor_persistent_student_codes.sql` — коды, сеансы, ограничения входа и выбор ника.
6. `20261117163649_tutor_student_workspace.sql` — статусы занятий, безопасный журнал ученика и привязка домашней работы к занятию.

Затем разверните `supabase/functions/tutor-student-access`. Исходник, import map,
конфигурация CLI и pinned-версия supabase-js находятся в репозитории. Функция
использует встроенные серверные SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY и
SUPABASE_ANON_KEY. Дополнительных платных сервисов и отправки писем не требуется.

`verify_jwt=false` установлен только для этого endpoint: вход проверяет код,
а административные действия сами проверяют Bearer через Auth.getUser и роль/
владельца в базе. Служебный RPC `tutor_code_gateway` доступен только service_role.
CORS разрешает основной домен, его текущий production alias и localhost:5173.
При подключении нового домена дополните список разрешённых origins функции.

`tutor.sql` — исторический снимок первого этапа, а не актуальная сводная схема.
Не выполняйте его поверх миграций. Источник схемы — `supabase/migrations`.
`tutor-smoke.sql` и `tutor-stage2-smoke.sql` проверяют живую базу с ROLLBACK;
временные пользователи второго скрипта также откатываются. Письма не отправляются.

### Первый преподаватель

Создайте аккаунт в собственном Supabase Auth проекта Tutor через
Dashboard, затем назначьте роль из SQL Editor от имени администратора базы:

```sql
insert into public.tutor_roles(user_id, role)
select id, 'teacher' from auth.users where lower(email) = lower('YOUR_EMAIL')
on conflict(user_id) do update set role = excluded.role;
```

В подключённом проекте роль уже назначена аккаунту пользователя. Ни кнопки,
ни user_metadata, ни самостоятельная регистрация Auth не предоставляют teacher.

Ученикам почта не нужна. Восстановление пароля преподавателя по-прежнему зависит
от почты Auth: разрешите адрес возврата `https://barkaloo-tutor.vercel.app/tutor/`
в Redirect URLs отдельного проекта Tutor. Настройки Auth других проектов не
изменяются. Доставка восстановления
преподавателя отдельно не заявляется проверенной.

## Как добавить ученика

1. «Ученики» → «Добавить ученика» → «Добавить и получить код». Имя для журнала необязательно.
2. Передайте ученику шестизначный код и адрес платформы. Код постоянный, сохраняет
   ведущие нули и подходит для повторного входа на разных устройствах. Это доступ
   к аккаунту, поэтому код не публикуют в учебных материалах.
3. Ученик выбирает «Я ученик», вводит код, при первом входе задаёт ник и оформление.
4. В карточке есть «Код для входа», копирование, замена и приостановка. Новый код
   сохраняет аккаунт, результаты и назначения; старый код и прежние сеансы теряют
   доступ к данным Tutor. Приостановленный вход можно разрешить снова.
5. Опубликуйте модуль, выберите «Только назначенные» для закрытого доступа и
   назначьте его в карточке. Затем выдайте работу из опубликованных заданий.

Имя для вашего журнала приоритетно, если заполнено; иначе отображается ник ученика.
Заметки карточки и комментарии журнала занятий видны только преподавателю;
комментарии домашней работы и оценки доступны ученику.

## Архитектура и права

Учебные операции идут через `public.tutor_api`: SECURITY INVOKER обёртка вызывает
закрытый SECURITY DEFINER диспетчер с проверкой auth.uid(), роли и владельца.
У функций фиксирован пустой search_path. Старые api_v1/api_v2 и внутренние
обработчики недоступны клиентам напрямую. Частную схему не открывайте в Data API.

Связи: sections → topics → modules/draft tasks → publications/published tasks →
attempts/progress. teacher–student links связаны с назначениями, домашними работами
и занятиями. У работы есть безопасные snapshots и отдельные private homework_keys;
у ручной попытки — сохранённые private attempt_keys. Все публичные таблицы защищены
RLS, прямые записи ролей, попыток и результатов у клиентов запрещены. Приватные
таблицы намеренно без клиентских grants и разрешающих политик.

Студенту возвращаются только доступные опубликованные снимки без правильных
ответов. audience=all открывает модуль всем вошедшим; assigned требует активного
назначения. Это проверяется также при прямом чтении тем, задач и Storage.

Числа сравниваются точным PostgreSQL numeric, строки — по заданным правилам
регистра/пробелов, множественный выбор — как множество. Приблизительного сравнения
нет. request_id защищает от дубликата отправки. Решение раскрывается по политике
автора. История ошибок сохраняется после исправления; последний ответ определяет
текущий статус. Ручную попытку оценивает владелец модуля; повторная оценка отклоняется.

Домашняя работа фиксирует условия, варианты, правильные ответы, критерии и правила
раскрытия. Изменение или снятие модуля с публикации работу не меняет. Для прекращения
новых ответов есть отмена. Поздние ответы разрешены. «Проверена» означает, что все
ответы оценены, и может включать ошибки; число верных показано отдельно.

Предпросмотр преподавателя использует отдельные попытки/прогресс и не увеличивает
реальные результаты. Ученик не может включить preview. Архивирование закрывает
личный доступ; для аккаунта с кодом закрывается также вход и доступ старых сеансов.
История сохраняется и возвращается при разрешённом новом входе.

### Постоянные коды и сеансы

Коды генерируются CSPRNG с равномерным распределением. В приватной схеме хранятся
HMAC для поиска и AES-GCM для повторного просмотра преподавателем. Секрет создаёт
база; он не попадает в исходники/клиент и не зависит от ротации service_role.
Обычный data/export не содержит кодов, шифротекста или ключей. Старые HMAC
резервируются навсегда, чтобы прежний код не открыл другой аккаунт.

PostgreSQL ограничивает входы: 5 за 15 минут на сетевой отпечаток, 5 на код,
60 в час на проект. Неуспешные запросы учитываются; успех не сбрасывает лимит.
IP хранится только в виде HMAC, старые счётчики очищаются. Глобальный предел не
зависит от заголовков IP. При большей нагрузке нужна отдельная настройка входа.

После проверки кода сервер получает Auth-сессию через generateLink/verifyOtp без
отправки письма. В браузер идут только собственные access/refresh tokens. Сеанс
регистрируется с поколением кода; RLS и каждый учебный RPC проверяют его вместе
с активностью связи. Старый refresh token после ротации не возвращает доступ.
Сеансы и глобальные настройки других аккаунтов не меняются.

Повтор создания с тем же request_id возвращает тот же аккаунт. code_requests
позволяет продолжить создание после сетевого сбоя. Исторические таблицы UUID-
приглашений сохранены для совместимости миграций, новый интерфейс их не использует.

### Файлы и содержимое

Изображения в приватном `tutor-images`: PNG/JPEG/WebP/GIF до 8 МБ, проверка
сигнатуры в клиенте, SVG/HTML и перезапись запрещены. Только владелец загружает
в папку модуля. Подписанная ссылка выдаётся на 5 минут; уже выданная ссылка может
дожить до истечения после закрытия доступа. Удаление неиспользуемых файлов в UI
пока не реализовано. Не удаляйте Storage metadata прямым SQL.

Видео — YouTube/Vimeo или HTTPS MP4/WebM. KaTeX работает с trust:false,
форматирование ограничено схемой Tiptap. Выполнения произвольного Python нет.

## Проверки и границы

Общие `ActivityChart` и `ReviewModal` находятся в `src/components/`: страницы
домашних работ и статистики не импортируют главную. Расчёты сводки преподавателя
сосредоточены в `src/lib/dashboard.ts`, а результатов домашних работ — в
`src/lib/teaching.ts`. Компоненты отображают результаты этих функций.
`homeworkSummary` группирует попытки один раз и возвращает `attemptsByItem`:
карточка работы и её общий результат используют одну и ту же последнюю попытку.
Новые массивы сортируются по времени без изменения общих данных приложения.
Проверки порядка попыток, разделения предпросмотра и часовых поясов находятся в
`test/client-data.test.mjs`; они выполняются командой `npm run test:tutor`.

`tutor/test` использует настоящий PostgreSQL в PGlite с Auth/Storage окружением:
публикации, пять типов ответов, RLS, снимки работ, ручная проверка, коды, роли,
ротация, отзыв сеансов и ограничения перебора. `codes.test.mjs` также проверяет
шифрование, ведущие нули и защиту от изменения шифротекста. TypeScript проверяется
для приложения и отдельно для Edge Function. Подробности браузерной и живой
проверки — в `VERIFICATION.md`. Учебные примеры ЕГЭ не генерируются для тестов.

Реализованы первые два этапа для личного обучения и базовой работы с учениками.
Прогресс завершения отмечает сам ученик; статус занятия задаёт преподаватель
независимо от его даты, посещаемость отдельно не ведётся. RPC пока без пагинации.
Для коммерческой эксплуатации нужны workspace/membership, аудит, масштабирование
входа и запросов, нагрузочная проверка. Группы, платежи, пробники, проверка файлов
и запуск программ третьего этапа не реализованы.

В существующей инфраструктуре остаются предупреждения sharp@0.34.5
(https://github.com/advisories/GHSA-wq5f-xc86-pv6w) и отключённой проверки утёкших
паролей Auth. Эти общие настройки не менялись. Данные и политики app_state
English/Fit миграциями Tutor не изменяются.

## Общий журнал ученика и преподавателя

Занятия имеют явные состояния planned/completed/canceled. Предыдущие записи,
которые раньше считались проведёнными по прошедшей дате, получили completed.
Перенос, проведение и отмена меняют ту же запись; домашние работы не отменяются.
Ученику API передаёт только его занятия при активной связи, без личного комментария
преподавателя. Прямой доступ ученика к сырым строкам tutor_lessons остаётся закрыт.

homework_create принимает необязательный lesson_id. Связь создаётся в той же
транзакции после проверки владельца, ученика и доступности занятия. Без lesson_id
работа остаётся отдельной. Используется существующая tutor_lesson_homework.

Открытая вкладка обновляет данные раз в 15 секунд и при возвращении к ней.
Обновления приостанавливаются для скрытой вкладки и несохранённого редактора.
После отправки ответа или изменения преподавателем выполняется немедленное обновление
текущего кабинета. Логика входа и независимые сеансы вкладок не менялись.

Статусы домашних работ рассчитываются из последних реальных попыток по всем заданиям.
Все ответы оценены — «Выполнена» (правильность показана отдельно); все отправлены,
но есть ручная проверка — «На проверке»; незавершённая работа с истёкшим сроком —
«Просрочена»; остальные активные — «Не выполнена». Отменённые видны в общем списке
и общем числе, но не входят в четыре активных категории. История и раскрытие решения
сохраняются по серверным правилам преподавателя.

Каталог КЕГЭ использует существующие разделы; категория полных вариантов пока пуста.
Банк заданий, импорт и вымышленные материалы не добавлены.

В рабочем проекте объединённая миграция шестого пункта применена четырьмя частями:
tutor_lesson_status, tutor_student_schedule_view, tutor_lesson_status_save,
tutor_homework_lesson_link. Содержимое трёх серверных функций сверено с исходником.
Локальные и рабочие версии миграций уже исторически имеют разные timestamps;
не запускайте автоматический db push без согласования истории миграций.

преподавателя также выведены уже существующие домашние работы и каталог.
Материалы организованы по существующим разделам ЕГЭ. Таблица tutor_theory_materials

Преподаватель добавляет документы, изображения, видео/аудио (до 50 МБ) или ссылку
YouTube/Vimeo. Ученики с активной связью видят материалы своих преподавателей.
RLS защищает метаданные и файлы, включая отзыв кода/архивирование ученика.
Загрузка проверяет расширение, сигнатуру и размер; bucket ограничивает MIME/размер.
HTML/SVG/исполняемые приложения не принимаются, Python хранится как текстовый файл.
Просмотр медиа использует подписанный URL на один час; уже выданная ссылка может
дожить до истечения после закрытия доступа. Скачивание получает Blob через
авторизованный Storage API и сохраняет с исходным именем. Документы Office/ZIP
открываются или скачиваются средствами браузера, встроенного офисного редактора нет.
Убрать материал означает архивировать запись, без удаления файла/данных.
Тёмная палитра обновлена на чёрную/графитовую со светлыми акцентами;
светлая зелёная тема сохранена.

### Режим урока

Рабочие области открываются из записи журнала. Доски используют миграцию
`20261121171559_tutor_lesson_workspaces.sql`.

Python выполняется в браузере в отдельном Web Worker внутри iframe с
`sandbox="allow-scripts"`. SourceCraft открывает iframe с
`https://barkaloo-tutor.vercel.app`, который должен быть разрешён в `frame-src`
страницы Tutor. На Vercel политика встраивания разрешает только этот же
адрес и основной сайт SourceCraft. Сборка Vercel добавляет
[Pyodide 0.27.7](https://github.com/pyodide/pyodide/tree/0.27.7) к статическим
файлам после проверки контрольной суммы пакета.

Для локального запуска подготовьте среду из корня репозитория:

```sh
node tutor/scripts/install-python-runtime.mjs tutor/public/python-runner/runtime
```
