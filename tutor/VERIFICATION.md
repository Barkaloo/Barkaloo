публикует его, проходит в режиме ученика и возвращается к сохранённым результатам.

Автотест `tutor/test/database.test.mjs` применяет обе миграции к настоящему
PostgreSQL в PGlite. Для Supabase-специфичных auth.uid и Storage-схемы задаются
минимальные окружения; проверка ответов и политики исполняются самим PostgreSQL.
Это не проверка доставки почты и не имитация успешного облачного развёртывания.
Работа с живым Supabase отдельно проверяется `supabase/tutor-smoke.sql` с ROLLBACK.

В первой попытке запуска двух старых archive-тестов Windows CRLF нарушили
побайтовое сравнение исходника и архива. Подтверждено, что после замены CRLF→LF
байты полностью совпадают. `.gitattributes` фиксирует LF для этих файлов;
содержание исходников English не менялось. После нормализации — 103/103 PASS.

Расширенный тест ручной проверки нашёл конфликт имени PL/pgSQL-переменной feedback
со столбцом. Исправление вынесено в отдельную миграцию; затем все типы ответов и
ручная проверка прошли. Имена файлов миграций синхронизированы с версиями,
зафиксированными MCP в supabase_migrations.schema_migrations.

В UI использовалась явно техническая временная тема, а не учебные материалы ЕГЭ.
Тестовые тема, модуль, задание, две попытки и прогресс удалены по точным UUID с
проверкой владельца. Один загруженный PNG из репозитория остаётся в приватном
Storage без ссылок из материалов; после удаления модуля его запрещают политики
чтения. В этой версии нет UI удаления неиспользуемых загрузок. Storage metadata
не удалялась прямым SQL, чтобы не создавать потерянные файловые объекты.

Второй и третий этапы не заявляются готовыми: ученические карточки, назначения,
домашние работы, журнал занятий, группы, оплата и запуск Python отсутствуют.
Опубликованные модули первой версии видны всем вошедшим ученикам.

Ограничения аудита: в существующей инфраструктуре есть предупреждения о sharp и
проверке утёкших паролей (см. README). Проверки не являются нагрузочным тестом,
аудитом внешнего SMTP или независимым пентестом.
