# Карточка ученика и домашние работы

Одна система используется обоими кабинетами. Новая миграция расширяет существующие
`tutor_homework`, `tutor_homework_items` и связь `tutor_lesson_homework`.

- `tutor_homework.requires_submission` — нужен отдельный ответ с ручной проверкой.
- `tutor_homework_resources` — ссылки и приватные файлы работы. Текст инструкций
  остаётся в существующем `comment`. Материалы не создают обязательных ответов.
- `tutor_homework_submissions` — история отдельных ответов, возвратов и проверок.
  Повтор отправки с тем же request_id не создаёт дубликат. Проверка устаревшего
  ответа отклоняется. Предпросмотр отделён флагом is_preview.
- `tutor_student_note_entries` — датированные личные заметки преподавателя.
  Прежний текст копируется в запись; исходные строки сохраняются. Удаление заметки
  скрывает её через deleted_at. Число записей не ограничено.

Правила статуса находятся в `src/lib/teaching.ts` и используются карточкой ученика,
списком работ и обоими журналами. Для завершения необходимы правильные/принятые
последние ответы на все обязательные элементы. Ошибки и возвраты требуют доработки.
Когда все ответы отправлены и остаётся только проверка, статус — «На проверке»;
иначе незавершённая работа после дедлайна — «Просрочена». Просрочка и отмена занятия
не изменяют попытки. Материалы без заданий и обязательного ответа сразу считаются
выполненной работой: это явно указано в форме назначения.

Все записи и проверки проходят через Tutor RPC с прежними проверками аккаунта,
роли и активной сессии кода. Новые таблицы имеют RLS и доступны клиенту только для
чтения; записи разрешает проверяющий владельца API. Ученику недоступны чужие работы,
заметки преподавателя и закрытые ключи проверки. Bucket `tutor-homework` приватный;
загрузить файл может преподаватель, прочитать — участник конкретной работы.
Прикреплённые файлы нельзя удалить через очистку незавершённых загрузок.
Файлы ограничены разрешёнными документами/медиа и 50 МБ; клиент проверяет сигнатуру.
Загрузка не исполняет Python или содержимое архивов. Файлы скачиваются как вложения.

Проверки: `node --test tutor/test/*.test.mjs`, TypeScript и production-сборка.
`student-workspace.test.mjs` использует настоящий PostgreSQL в PGlite с RLS и всеми
миграциями: смешанная работа, приватность файлов/заметок, ручная проверка, доработка,
сохранение истории, материалы без ответа, просрочка и независимая отмена занятия.
Браузерный сценарий выполнялся на изолированной локальной базе через HTTP; загрузка
и чтение тестового PDF использовали локальный адаптер файлов. Это не проверка
реального Supabase Storage с учётными данными рабочего ученика.
